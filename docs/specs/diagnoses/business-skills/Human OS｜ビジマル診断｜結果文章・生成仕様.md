## 3. セクションの役割

| セクション | この欄だけが答えること |
|---|---|
| このタイプについて | 結局どんな人か。スマホで長くスクロールせず理解できる概要。 |
| 辛辣な一文 | 本人が無自覚に繰り返す癖を一文で刺す。**本文は表示しない。** |
| スキルバランス | 回答から観測された5能力の出方。実技能の絶対評価ではない。 |
| ビジネススタイル | 4軸の位置と4文字コード。 |
| 仕事の思考回路 | 何を見て、どう整理し、どう決めるか。弱みや改善策を書かない。 |
| 強み | 思考・行動が生む具体的な価値。 |
| 弱み | 日常的に起きる失敗、摩擦、コスト。 |
| 致命的な弱点 | 強みと複数の弱みが重なった先の重大な破綻。 |
| 成長ヒント | 破綻を防ぐ具体的な行動。 |
| キャリア適性 | 力が出る環境、裁量、課題、評価条件。 |
| 向いている仕事 | 職業名3件と、その中で合う具体的な役割。 |
| 避けたい仕事 | 職業の優劣ではなく、進め方が噛み合いにくい職業と条件。 |
| 人間関係 | 信頼、距離、伝え方、衝突、修復。 |
| チームでの役割 | どこへ配置し、誰と組ませ、何を任せるか。 |
| 結論 | タイプの価値と最重要課題を最大2段落程度で示す。 |

段落数は統一しない。内容の深さ・納得感・当たっている感を優先し、同じ論点を別セクションで言い換えない。

## 4. 固定文章スキーマ（fixed-copy.json）

実装スキーマ：`src/schemas/diagnosis.ts` の `FixedCopySchema`

| フィールド | 型 | 用途 |
|---|---|---|
| `typeId` | string | タイプ ID（固定名称・IDマスター §2 参照） |
| `catchCopy` | string | キャッチコピー（英語名の下） |
| `overview` | string | このタイプについて |
| `sarcasticTitle` | string | **辛辣な一文（これのみ表示）** |
| `sarcasticBody` | string | 辛辣コメント本文（**画面に表示しない**） |
| `thinkingProcess` | string | 仕事の思考回路 |
| `strengths` | string[] | 強み（複数） |
| `weaknesses` | string[] | 弱み（複数） |
| `fatalWeakness` | string | 致命的な弱点 |
| `growthHint` | string | 成長ヒント |
| `careerFit` | string | キャリア適性 |
| `goodJobs` | `{title, detail}[]` | 向いている仕事（3件） |
| `badJobs` | `{title, detail}[]` | 避けたい仕事（3件） |
| `relationships` | string | 人間関係 |
| `teamRole` | string | チームでの役割 |
| `conclusion` | string | 結論 |

### 職種制約

- 向いている仕事：同一ラベル最大2タイプ
- 避けたい仕事：同一ラベル最大2タイプ
- 職業の格付けに見える禁止表現は0件（「コールセンタースタッフ」等を低位職として列挙しない）
- 向いている仕事・避けたい仕事どちらも、職業として想像できる粒度に統一

## 5. 4軸動的文章スキーマ（dynamic-copy.json）

実装スキーマ：`src/schemas/diagnosis.ts` の `DynamicCopySchema`

全 25 パーツ。各パーツは以下の条件で選出する。

| フィールド | 内容 |
|---|---|
| `id` | パーツ ID |
| `targetSlot` | 挿入先セクション |
| `condition` | dominant / soft / balanced とその軸 |
| `text` | 挿入文章 |

動的文章の実データは `data/diagnoses/business-skills/dynamic-copy.json` を参照。

---

## 6. 辛辣表示ルール

- `sarcasticTitle` のみ画面に表示する
- `sarcasticBody` は JSON に存在するが、**V1 では画面に表示しない**
- 見出しなしで表示する（「辛辣コメント」等の見出しを付けない）

---

## 7. スキルバランスの表示

- 五角形レーダーと数値は画面表示スコア D（50〜100）を使用
- 内部 V 値や特化個体判定値と混同しない
- 推奨注記：「回答から観測された仕事上の行動傾向を、比較しやすい50〜100の表示スコアで示しています。実技能の達成率や順位ではなく、50も能力不足を意味しません。」

---

## 8. 異常時の動作

- `av` パラメータが不正：スキルバランスと特化個体を非表示
- `ta`/`os`/`st`/`dc` パラメータが欠損：`types.json` の `representativeScores` をフォールバック使用
- 存在しない typeId：エラー画面（「診断結果を確認できませんでした」）

## 11. V2文章の責任分離

| データ | 責任 |
|---|---|
| 選出されたサブルート本文 | 思考順序、強み場面、壊れる因果、環境、職種、補完タイプ、改善行動 |
| 4軸実数値 | 同タイプ内での仕事スタイルの方向と強度 |
| 5能力実数値 | 回答時点で観測された能力の使われ方 |
| 回答証拠 | 主ルート・サブルート選出の根拠 |
| 数値補正 | 今回の出方、強さ、柔軟性の限定追記 |

固定本文と数値補正に同じ説明を重複させない。数値補正によって主ルート・サブルートの人物像を変更しない。

## 12. V2数値補正上限

### 今回のあなた

- 上位能力：最大2
- 相対的に遅れる能力：最大1
- 軸補正：最大1組
- low時：上位能力1、軸補正1組まで

### 数値から見る、今回の特徴

- 上位軸：2
- 中央に近い軸：1
- 上位能力：2
- 相対的に遅れる能力：1

### この考え方がうまく働かなくなる時

- 分岐固有因果：必須
- 数値補正：最大2
- low時：最大1

### 一つだけ変えるなら

- 分岐固有の改善行動1つのみ
- 数値による別案への差し替えは禁止

最低能力は能力不足と断定しない。50を平均と呼ばない。

## 13. V1とV2の切替

- 本番は、V2コード実装・QA・公開承認までV1を継続する
- V2正本の確定だけで`fixed-copy.json`、`dynamic-copy.json`、コードを変更しない
- V2実装時は旧V1文章を上書きせず、ロールバック可能な構造で追加する
- V2公開後にV1データを削除するかは別途決定する

## 14. V2シェア文

- 1行目はタイプ名のみ
- 「でした。」は禁止
- 続けて強みと改善点を短く記載する
- 内部ID、主ルート名、サブルート名、確信度を含めない
