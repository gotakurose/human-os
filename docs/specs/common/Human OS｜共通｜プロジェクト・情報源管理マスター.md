# Human OS｜共通｜プロジェクト・情報源管理マスター

> 文書状態：正本・運用中
> 更新日：2026年7月10日
> 対象：Human OS 全体

---

## 1. Human OS の情報源構造

### 一次情報源（最優先）

| 種別 | 場所 |
|---|---|
| 正本仕様書 | `docs/specs/` |
| 実装コード | `src/` |
| 実装 JSON | `data/` |
| 静的アセット | `public/` |

### 参照優先順位

1. ユーザーの最新の明示指示
2. 対象診断の最新正本仕様書（`docs/specs/diagnoses/{diagnosisId}/`）
3. 実装コード・実装 JSON・本番公開挙動
4. 共通仕様書（`docs/specs/common/`）
5. 過去資料・旧仕様書・会話履歴

正本と実装が不一致の場合、どちらかへ自動的に合わせない。差分を「コード誤り」「文書誤り」「判断が必要」に分類して報告する。

---

## 2. 共通仕様と診断固有仕様の分離

| 分類 | 場所 | 記載内容 |
|---|---|---|
| 共通 | `docs/specs/common/` | Human OS ブランド、トップ、共通 metadata、法務、外部送信方針 |
| 診断固有 | `docs/specs/diagnoses/{diagnosisId}/` | 質問、採点、タイプ、文章、UI、QA |

同じ仕様を共通仕様と診断固有仕様に重複記載しない。

別の診断の仕様を、作業中の診断の仕様文書へ混入させない。

---

## 3. ファイル命名規則

```
Human OS｜{スコープ}｜{内容}.md
```

- スコープは「共通」または「診断の正式名称」（例：ビジマル診断）
- ファイル名に V1、FIX、final、最終版、最新版、ドラフトを含めない
- バージョン・状態・更新日は文書冒頭のメタ情報で管理する

---

## 4. 文書の種別

| 種別 | 保存場所 | 説明 |
|---|---|---|
| 正本 | `docs/specs/` | 設計・仕様の唯一の正解 |
| 実装 JSON | `data/` | 実行用データ。仕様書と役割が異なる |
| アーカイブ | （リポジトリ外） | 旧仕様書・検討履歴。参照しない |

正本に記載された仕様が、実装 JSON や実装コードと一致しているか確認すること。

## 6. 新しい診断を追加する際の標準構成

```
docs/specs/diagnoses/{diagnosisId}/
├── Human OS｜{診断名}｜総合・運用マスター.md
├── Human OS｜{診断名}｜固定名称・IDマスター.md
├── Human OS｜{診断名}｜質問・採点・判定仕様.md
├── Human OS｜{診断名}｜結果文章・生成仕様.md
├── Human OS｜{診断名}｜UI仕様.md
└── Human OS｜{診断名}｜実装・QAチェックリスト.md
```

診断一覧・ID管理マスターへ diagnosisId を追加してから正本フォルダを作成する。

---

## 7. ロック済み仕様の変更禁止

ロック済みと明記された仕様は、明示的な再決定なしに変更しない。変更が必要な場合は、ユーザーへ差分と影響範囲を報告してから対応する。

---

## 8. 診断固有内容の共通資料への混入禁止

質問文、タイプ名、タイプ ID、採点詳細、文章コピーは診断固有の正本へ記載する。共通仕様文書に記載しない。

診断の正式名称と diagnosisId を参照する場合は、`Human OS｜共通｜診断一覧・ID管理マスター.md` を参照元とする。
