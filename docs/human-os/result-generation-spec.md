Human OS / ビジマル診断
結果文章・生成仕様書

【目的】

16タイプの固定文章と、4軸・5能力値による動的文章を組み合わせ、
同じタイプでも回答傾向によって「自分専用」と感じられる診断結果を生成する。

文章量の短さよりも、密度・具体性・信頼性・本質感を優先する。
ただし、同じ内容の重複や冗長な言い換えは避ける。

2. 辛辣コメントの役割
────────────────

辛辣コメントは、本人が日常的に繰り返しているのに、
自分では合理的だと思っている「無自覚な癖」を暴く欄。

役割：
・結果ページ前半の最大フック
・「えっ、そうなんだよね」と思わせる
・以降の詳細を読みたくさせる
・本人の自己認識と、周囲からの見え方のズレを示す

構造：
・見出し：一文で本質を刺す
・本文：なぜそうなるか、本人にはどう見えるか、周囲にはどう見えるかを説明

辛辣コメントで扱うもの：
・現在進行形の無自覚な癖
・本人が合理的だと信じている判断
・日常的に繰り返す行動
・周囲との認識差

扱わないもの：
・将来的な破綻
・最悪の失敗シナリオ
・人格否定
・単なる悪口
・弱み欄の言い換え

────────────────
3. 致命的弱点の役割
────────────────

致命的弱点は、そのタイプの癖が悪化した時に、
仕事・組織・事業をどう壊すかを示す欄。

役割：
・重大な失敗パターンを示す
・強みがどのように裏返るかを示す
・本人が失いやすいものを明示する
・将来的な破綻を警告する

構造：
・見出し：破綻の核心
・本文：引き金、崩れ方、周囲への影響、失うもの

辛辣コメントとの違い：

辛辣コメント：
「今、本人が無自覚に繰り返していること」

致命的弱点：
「そのまま進んだ先で起きる重大な破綻」

両者で同じ内容を繰り返さない。

5. セクションごとの固定・動的構造
────────────────

共通原則：

結果画面で使用するすべての文章枠には、
タイプごとの固定基準文を用意する。

動的文章は固定基準文へ無制限に追記するのではなく、
指定されたスロットの置換または限定的な追記として使用する。

動的条件に該当しない場合や、
複数条件の競合によって採用文が決まらない場合は、
必ずタイプ固定の基準文を表示する。

これにより、
文章の欠損、空欄、不自然な単純連結を防ぐ。

キャッチコピー：

・タイプ固定
・動的置換なし

タイプ概要：

・タイプ固定の基準本文を必須とする
・最強軸または重要な組み合わせによって、一部追記または置換可能
・固定70％、動的30％程度を目安とする

辛辣コメント：

・タイプ固定の基準見出しと基準本文を必須とする
・最強軸、最低能力、重要な組み合わせに応じて全文置換可能
・固定文と動的文を同時に連結しない

仕事の思考回路：

・タイプ固定の基準本文を必須とする
・4軸または重要な組み合わせによって一部追記または置換可能
・固定60％、動的40％程度を目安とする

強み：

・タイプごとに固定基準文を3項目用意する
・強み1、強み2は原則固定
・強み3は動的文章による置換対象
・適切な動的文章がない場合は固定の強み3を表示する

弱み：

・タイプごとに固定基準文を3項目用意する
・弱み1は原則固定
・弱み2、弱み3は動的文章による置換対象
・適切な動的文章がない場合は固定の弱み2、弱み3を表示する

致命的弱点：

・タイプ固定の基準見出しと基準本文を必須とする
・最強軸、最低能力、重要な組み合わせに応じて全文置換可能
・固定文と動的文を同時に連結しない

成長ヒント：

・タイプごとに固定基準文を3項目用意する
・弱み、最低能力、致命的弱点に応じて各スロットを置換可能
・適切な動的文章がないスロットには固定基準文を表示する

キャリア適性：

・タイプ固定の基準本文を必須とする
・軸強度または重要な組み合わせによって限定的に補正可能

向いている仕事：

・タイプごとに固定の3職種と理由本文を用意する
・原則として動的置換しない

避けたい仕事：

・タイプごとに固定の3職種と理由本文を用意する
・原則として動的置換しない

人間関係：

・タイプ固定の基準本文を必須とする
・I / G、営業力、管理力、重要な組み合わせによって置換可能

チームでの役割：

・タイプ固定の基準本文を必須とする
・原則として固定中心
・重要な組み合わせに限り一部補正可能

結論：

・タイプ固定の基準本文を必須とする
・最強軸または最大の課題に応じて一部置換可能
・固定の核心を失わない

6. キャリア欄の構造
────────────────

キャリア適性：
どのような環境・裁量・課題・評価方法で力が出るかを書く。

向いている仕事：
具体的な職種・役割を3つラベル表示し、その下に理由を書く。

避けたい仕事：
相性が悪い職種・役割を3つラベル表示し、その下に消耗する理由を書く。

「能力がない」「絶対に向いていない」と断定しない。
仕事内容と本人の認知特性が噛み合わない理由を説明する。

7. 文体
────────────────

・高級な診断書、個体票、ドシエ

・優しくするために本質をぼかさない

・本人と周囲の認識差を具体的に描く
・文章量より密度を優先
・必要なら長くしてよい
・全タイプで辛辣さと深度を揃える

8. 重複禁止
────────────────

・辛辣コメントと致命的弱点の重複
・概要と仕事の思考回路の重複
・強みとキャリア適性の重複
・弱みと避けたい仕事の重複
・結論で全文を要約するだけ
・全タイプに同じ強みや弱みを使う
・動物イメージだけで性格を説明する
・4軸の定義をそのまま本文へ書く
・同じ文型を16タイプへ使い回す

10. avパラメータ仕様（5能力値）
────────────────

URLパラメータ名：
av

形式：
1.{logicU}.{executionU}.{salesU}.{creativityU}.{managementU}

フィールド：
・先頭の "1" はスキーマバージョン
・logicU〜managementU は各能力の生スコア U_k（整数）

U_k の値域：
・logic       : 0〜24（寄与質問数 n_k=12、2点満点×12）
・execution   : 0〜16（n_k=8）
・sales       : 0〜8（n_k=4）
・creativity  : 0〜14（n_k=7）
・management  : 0〜10（n_k=5）

表示スコアへの変換：
V_k = Math.round(50 × U_k / n_k)

例：
av=1.18.10.5.11.7
→ logicU=18, executionU=10, salesU=5, creativityU=11, managementU=7
→ logic V = Math.round(50×18/12) = 75
→ execution V = Math.round(50×10/8) = 63
→ sales V = Math.round(50×5/4) = 63
→ creativity V = Math.round(50×11/7) = 79
→ management V = Math.round(50×7/5) = 70

avパラメータなし・不正値の場合：
5能力値セクションと特化個体バッジを非表示にする。

avパーサー検証（厳密）：
・形式: /^1\.(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$/
・拒否対象: スペース、符号(+/-)、小数点、科学記法(e)、先頭ゼロ、全角数字、タブ・改行
・Number()の暗黙変換を使わず正規表現で事前フィルタリングする

（schemaVersion=1、36エントリ）
