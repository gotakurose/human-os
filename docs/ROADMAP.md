# ROADMAP.md — 開発ロードマップ

## 全体方針

- **Phase 1 でプラットフォームの骨格を完成させる**。その後は診断データとエンジン実装を追加するだけ
- 各フェーズは独立してデプロイ・公開できる単位で区切る
- 診断ごとに個別コードを書かない。汎用エンジンを拡張していく設計を守る
- コードの大規模な書き直しなしに次のフェーズに進めることを設計の前提とする

## Phase 2：家買いたい？現在地チェッカー

**目標：条件検索型ロジックのエンジン拡張 + 実用型不動産診断のローンチ**

### 概要

住宅購入を検討しているユーザーが条件を入力すると、現実的な候補地を提示する実用型診断。単なる「フェーズ診断」ではなく、条件から候補を絞り込む条件検索型の体験を提供する。

### 入力項目

- 予算（万円）
- 駅徒歩（分以内）
- 築年数（年以内 or 新築希望）
- 希望間取り（1LDK / 2LDK / 3LDK 等）
- 希望面積（㎡以上）

### 出力

- 現実的な候補地 3つ（エリア名）
- 新宿までの所要時間
- 想定価格帯
- 想定物件像（「駅徒歩8分・築15年・3LDK・65㎡・3,800万円前後」等）
- 辛辣コメント 1つ（条件に対して現実的な一言）

### やること

- [ ] 条件検索型ロジックの汎用エンジン拡張
  - `branch` エンジンのスケルトンを完全実装
  - 条件入力 → 候補エリアフィルタリング → 結果返却のロジックを汎用化
  - 診断ごとに個別コードを書かない。エンジン側で条件検索を汎用的に処理する
- [ ] 相場データの JSON 管理
  - 初期 MVP では API は使わず、主要エリアの簡易相場データを JSON で管理
  - `data/diagnoses/house-check/areas.json` に候補エリア・価格帯・交通データを定義
- [ ] 家買いたい？チェッカーの JSON データ作成
- [ ] 住宅ローン・不動産サービスへのアフィリエイトリンク設置
- [ ] Google AdSense 申請（Phase 1 の PV が条件を満たした段階で申請）
- [ ] 診断一覧ページのカテゴリフィルタ追加

### Phase 2 でのコード変更について

Phase 2 では `branch` エンジンの実装と条件検索ロジックの追加が必要なため、`src/engine/` へのコード追加が発生する。これは問題ない。ただし、家買いたい？チェッカー専用のコードは書かない。**汎用エンジンへの機能追加**として実装し、他の診断でも同じロジックを再利用できる設計を守る。

### 完了の定義

- 条件入力 → 候補地3件提示の診断フローが動作している
- 辛辣コメントが表示される
- 住宅系アフィリエイトリンクが設置されている
- Google AdSense が承認され、広告が掲載されている

## Phase 3：オリジナル16タイプ診断

**目標：`type16` エンジンの完全実装 + フラッグシップ診断のローンチ**

### やること

- [ ] `type16` エンジンの完全実装（`engineType: "type16"`）
  - 4軸 × 2択でオリジナルタイプコードを生成
  - types.json からタイプ定義を取得
- [ ] オリジナル16タイプの設計
  - MBTI とは異なる**独自の4軸・独自コード・独自タイプ名**で設計
  - EI / SN / TF / JP 体系・ENTJ / INFP 等のコードは使わない
  - タイプ名はオリジナルの日本語名称（例：「先読みの設計者」「直感の開拓者」）
  - 各タイプにオリジナルキャラクター・ビジュアルを設定
- [ ] 各タイプの定義に以下を含める
  - 向いている職種（`recommendedRoles`）
  - 向いている環境（`idealEnvironments`）
  - 苦手な環境（`challengingEnvironments`）
  - 相性タイプ（`compatibleTypes`）
  - 成長アドバイス（`growthTips`）
  - 辛辣コメント候補（`sarcasticComments`）
  - 有名人例は含めない
- [ ] 結果ページの強化
  - タイプ別分布（「このタイプは全体の○%です」）
  - 相性タイプへのリンク
- [ ] X Card / OGP の強化（タイプキャラクターを前面に出したビジュアル）

### 完了の定義

- 16タイプ全ての結果ページが SSG で生成されている
- X シェア時に魅力的なキャラクター OGP が表示される
- 月間 10,000 PV を超えるトラフィックが見込める診断になっている

## Phase 5：収益化の本格最適化

**目標：広告・アフィリエイト・有料レポートの最適化 + BtoB 展開の準備**

Phase 1〜4 で最低限の収益化は始まっているが、Phase 5 では規模拡大に合わせて収益構造を本格的に最適化する。

### やること

- [ ] Google AdSense の最適化（プレースメント・フォーマット・ABテスト）
- [ ] アフィリエイト連携の拡充（診断カテゴリごとに最適なリンクへ整理）
- [ ] 有料 PDF レポートの自動生成
  - 購入後に PDF を自動配信
  - AI 生成テキスト + デザインテンプレートで構成
- [ ] BtoB ダッシュボード（ベータ）
  - チーム全員の診断結果を管理者が確認できる
  - 組織の強み・弱みの可視化
  - 月額 SaaS プランの検討

### 完了の定義

- 月間収益が広告・アフィリエイト・有料レポートの合計で安定している
- BtoB 顧客との最初の契約
